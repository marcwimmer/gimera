Bumping the pin of an `integrated` repo updates the vendored files again. Two independent shortcuts kept the old content while `gimera.yml` already claimed the new sha — `apply` reported success, and nothing pointed at the disagreement. First, the fast path decided "already up to date" by comparing the sha from `gimera.yml` against itself, which is true by construction and therefore skipped every bump; it now compares the git tree of the wanted commit against the tree of the vendored directory as committed in the parent repo, and re-extracts whenever that cannot be established or the working tree has local changes. Second, the extract copies with `rsync --checksum` instead of rsync's default size-and-mtime check: `git archive` stamps every file with the commit time, so two commits made within the same second carry identical mtimes, and a change that leaves the file length untouched keeps the size equal as well — rsync then considered the file unchanged and kept the old one. Re-applying an unchanged pin still skips the extract entirely, so the optimization survives; the checksum comparison is only reached once something actually differs.
