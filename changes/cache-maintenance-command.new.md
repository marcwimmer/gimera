New `gimera cache` command to see what the golden cache is holding and to prune it. `gimera cache list` shows every entry with its size, the size of a leftover tarball from an older gimera, and how long it is since the entry was last updated — on the machine this was written on that turned up 74 entries, 30.5 GB of caches plus 28.6 GB of dead tarballs. `gimera cache clean` removes the tarballs, including those whose cache directory is already gone: the automatic cleanup runs from `_get_cache_dir` and is only ever reached for a URL still in use, so a tarball belonging to an entry nobody looks up any more would otherwise stay forever. `gimera cache clean --unused-for DAYS` additionally offers to remove entries that have not been updated for that long; it lists them, says that the cost is a fresh clone rather than lost data, and asks before deleting. Entries go stale without anyone noticing — the naming scheme dropped `_` and the `user@` part at some point, and test or temp repositories carry a path in their cache name that stops existing when the run ends — and neither case can be told from the mangled directory name, which is why age is the criterion and the user confirms.
