Integrated repos whose path is gitignored and untracked are no longer staged or committed into the parent repository - the files are pulled as before, but stay untracked. That is what odoo.sh style projects need, where `odoo/enterprise` is gitignored. The decision is taken once per repo with `git check-ignore` (index aware on purpose: a path that is *tracked* today counts as not ignored and keeps being committed, so nobody silently ends up with stale content in the parent repo). Until now this only worked by accident - `git status` does not report ignored files, so the final `git add` was skipped, while `commit_dir_if_dirty(..., force=True)` earlier in the run committed the content anyway whenever the path was already tracked. On `gimera apply` the skip is now stated instead of guessed from a failing `git add`. For the case that a path is tracked today and shall stop being tracked, the new gimera.yml repo option `dont_commit: true` (accepted as `local: true` as well) forces the same behaviour; it is only valid for `type: integrated`, since a submodule without its gitlink in the parent repo would not be a submodule.
